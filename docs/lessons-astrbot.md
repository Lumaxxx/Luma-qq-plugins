## 一、对方踩过的坑（原文结论）

| # | 坑 | 结论 |
| --- | --- | --- |
| 1 | AstrBot 在系统提示前注入 Safe Mode，角色扮演被压成客服腔 | 人格必须关掉安全模式；越靠后的规则权重越高，节奏规则要放末尾 |
| 2 | 表情包经 `context.send_message` 直发，绕过了钩子 | 发完要在对话里补一条「（我刚发了表情包，分类：xxx）」，否则上下文断裂 |
| 3 | 自适应概率调节器连乘 0.65，概率被压到 0 | 表现为「聊得越起劲越突然不说话」，必须关掉 |
| 4 | `after_reply_probability=0.75` 且上限 0.55 | 一接上话接下来 5 分钟几乎每条都回，「谁都回」 |
| 5 | 禁言时仍跑完整链路 | 生成完发送被拦，白烧 token；需要禁言检测 |
| 6 | `recent_memory_count=2` 无条件注入最近记忆 | 记忆被拿来「硬找话题」，必须按相似度+重要度过滤 |
| 7 | 记忆注入是长散文（单条 800 字、top_k 5） | 改 300 字 / top_k 3，只留事实点 |
| 8 | 办公技能提示词混进群聊 system prompt | 3400 字把模型推向「先说明再作答」的助手腔，删掉每轮省 1000 token |
| 9 | `mood_persistence_hours` 只写库、读取时不看时间 | 情绪永远挂着，压住新设定的语气；必须加过期判定 |
| 10 | 情绪系统给群聊加「生气」状态 | 群聊明显比私聊冲，需要能清掉负面情绪 |
| 11 | 记忆作用域只有单模式 | 群记忆应按群共享、私聊按人；召回时合并两个作用域 |
| 12 | 频繁强杀/重启 NapCat + 密码登录触发短信 | 被 QQ 风控 `ErrCode 3` 反复掉线；处置是「两天不动它」 |
| 13 | 数据库会话被写成字符数组 | `Input should be a valid dictionary`；写库前必须停实例 + 类型防御 |
| 14 | 刁难性问题顺着对方框架算 | 被牵着走；人格要写明「可以不答、可以反怼」 |

### 💡 可选（外挂就能做）

- **每日 token 日报**：解析 `qq-groupmate.log` 的 `用量 prompt=/输出=` 行，按天汇总调用次数、命中率、花费估算，写进 `amem.log` 或单独文件
- **事件重要度门槛**：只写 importance ≥2 的事件，减少「硬找话题」
- **记忆召回抑制**：外挂写事件时加 `weight` 上限，避免旧事件天天冒出来

## 三、还需要注意的运维结论

1. **少重启**：对方 5 次掉线后处置是「两天不动它」。我们这两天重启十几次，风险同源。以后只在必要时重启，避免连续快速重启。
2. **登录态刚恢复时别折腾**：扫码后 5 分钟内不要重启 NapCat。
3. **写数据前先停实例**：对方数据库被写坏就是没停实例；我们要改 `state.json` 时同理。
4. **别用密码登录**：会触发短信验证、抬高风控分。

## 四、一句话总结

阿圆现在缺的不是功能，而是**「说完记得自己说过什么」**和**「克制」**：
- 说了什么（表情包、主动发言）要进历史 → 需要一个小接口
- 记忆、老梗、说话长度都要有配额 → 已写进人格，观察效果
